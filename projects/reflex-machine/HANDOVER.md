## 1. What is finished

**The board is done and verified** - `projects/reflex-machine/`, version 2 (2026-09-16):
- 160 x 125 mm, 2 layers, **all through-hole parts** (the user cannot solder SMD).
- Arduino Mega 2560 plugs underneath as a shield; ESP32 DevKit V1 (30-pin) in sockets on top.
- 10 electromagnet drivers (IRLZ44N + 1N5822 + indicator LED), optocoupler coin input, filtered buttons,
  status LEDs, 74HC595 + 7-segment driver, 12V->5V via a 3-pin module (K7805-2000R3), fuse + surge protection.
- Spare headers: J16 2x10 (Mega: I2C, Serial3, SPI, D4/D13/D30-D33, A7/A8, 5V/3V3/GND), J17 2x4 (ESP32 GPIOs).
- Part values, section headings and Arduino pin names are printed on the silkscreen.
- Checks: netlist compare 0 differences, ERC clean, DRC **0 errors / 0 unconnected / 0 parity issues**.
  ~213 silkscreen warnings are expected (values printed over pads; the fab trims them).
- Outputs: `out/fab/` (gerber zip, BOM, CPL), `out/docs/` (STEP, schematic PDF, 3 renders, full BOM).

**Everything is generated by scripts** in `projects/reflex-machine/gen/` - never hand-edit the KiCad files:
`netlist.py` (single source of truth) -> `make_sch.py` / `check_sch.py` -> `make_pcb.py place|route|finish|check|render`
-> `make_outputs.py`. Rebuild from scratch takes ~5 minutes.

## 2. What was in progress (testing pipeline, 4 stages)

Building a **testing pipeline** so the user can trust the design before/after manufacturing, validating the
real design files rather than a generic recreation. See `test/README.md` for the live status table.

- **Stage 1 (electrical check on the real PCB file) - done, pass.** `test/electrical/REPORT.md`.
- **Stage 2 (SPICE on the real schematic's analog subcircuits) - done.** `test/spice/REPORT.md`. Installed
  LTspice (`winget install AnalogDevices.LTspice`), fixed 3 bugs in the vendored `spice` skill's LTspice
  backend (see `docs/LESSONS_LEARNED.md` section 8). Result: all 9 debounce/noise-filter RC networks
  (coin optocoupler + 4 button filters) confirmed within 0.24% of calculated cutoff. Also found the
  Mega-TX/ESP32-RX level-shifter divider runs at 3.33V (5V source, not the 3.3V the automated testbench
  assumed) - safe, ~270mV under the ESP32's ~3.6V absolute max, but worth knowing. Voltage-divider and
  decoupling/PDN automated checks hit separate template-generator bugs (not LTspice issues) - not yet fixed,
  verified by hand instead.
- **Stage 3 (Wokwi functional/logic sim) - input wiring confirmed, full game-round logic not yet checked.**
  `test/wokwi/diagram.json` generated from the real `gen/netlist.py` pin map and the firmware's actual
  segment bit order. User provided a `WOKWI_CLI_TOKEN` (free tier, 50 min/month - be sparing, 13s used so
  far, see `test/wokwi/USAGE_LOG.md`). CLI lint caught and fixed 29 real pin-name errors; a scripted
  scenario (`scenario_inputs.yaml`) pressed each of S1/S2/S3/RST/coin against the real compiled firmware
  and confirmed every one pulls exactly the right Mega pin LOW - all 5 passed. Full game-round behavior
  (magnet sequencing, 7-seg score, coin accumulation) not yet checked - the magnet outputs are PWM, so a
  simple pin-state assertion would be timing-flaky; would need a VCD capture instead. Costs more
  simulation minutes - ask before running it.
  Also working, stage-independent: `test/pinmap.py` (26 signals, 0 mismatches) and `sim/mega/`
  (firmware builds, 11 KB flash/1.5 KB RAM). `sim/esp32/` project created, not built yet.
- **Stage 4 (physical bring-up) - ready, waiting on the manufactured board.** `test/bringup/self_test.ino`
  (isolated per-subsystem checks: status LEDs, 7-seg count, each magnet pulsed briefly, all 4 buttons,
  coin input) + `test/bringup/CHECKLIST.md` (pre-power visual/continuity checks, power-up sequence,
  per-subsystem pass criteria, the still-open real-magnet-current measurement, then the ESP32 half).

Proteus was considered for stage 3 and dropped (no ESP32 model in the user's Proteus 8; this game needs
both boards). Wokwi covers Mega + ESP32 + 74HC595 + 7-segment + buttons and runs the real compiled code.

## 5. Manufacturing finding (2026-09-18, from `MANUFACTURING.md`)
Closest two holes are **0.489 mm** apart edge to edge (a GND via at 126.00, 152.00 next to the Mega's
GND pad A1 GND3) - just under JLCPCB's typical 0.5 mm hole-to-hole. Same net, so no short risk; fabs
usually accept it. KiCad's DRC doesn't flag it (its default rule is 0.25 mm). Not changed - the board is
signed off; move that via on the next rebuild if the fab objects.
